## ProcessBench (primary)

- Source: Zheng et al. (2024), arXiv:2412.06559; HF `Qwen/ProcessBench`.
- Live layout: one config `default`, four splits = difficulty tiers:
  gsm8k 400, math 1,000, olympiadbench 1,000, omnimath 1,000 (3,400 rows).
- Columns: `id`, `generator` (12 open models, 1.5B-72B), `problem`, `steps` (list of
  strings), `final_answer_correct` (bool), `label` (int).
- `label` = **0-indexed** index of the earliest erroneous step, `-1` when every step is
  correct. 272 rows have `label = 0`; no row has `label = n`. The loader converts to the
  paper's 1-indexed `e = label + 1`.
- 3,400 rows contain 2,842 distinct problems (olympiadbench 561, math 955, omnimath 951,
  gsm8k 375); no problem appears in two tiers. Grouping uses a hash of the problem text.
- 2,221 rows (65.3%) have a process error; 1,700 (50.0%) have an incorrect final answer;
  521 have a process error but a correct final answer; no row has a correct process and an
  incorrect answer.
- Minimum steps per trace 2, median 7, maximum 47, so rule P5 removes nothing.

## BIG-Bench Mistake (cross-domain)

- Source: Tyen et al. (2024), Findings of ACL; repository `WHGTyen/BIG-Bench-Mistake`
  (the brief's "Google Research GitHub" pointer; this is the authors' official release).
  Downloaded by `make data` from `raw.githubusercontent.com` (five JSONL files, ~3.3 MB).
- Traces generated by PaLM 2-L (Unicorn) for five BIG-Bench tasks: dyck_languages 986,
  logical_deduction 300, multistep_arithmetic 300, tracking_shuffled_objects 300,
  word_sorting 300 (2,186 rows, every input distinct).
- Fields: `input`, `steps`, `answer`, `target`, `mistake_index` (**0-indexed**, `null` =
  no mistake - stated in the dataset README). Correctness = exact match after whitespace
  normalisation, the matching rule the authors describe.
- 78.1% have a mistake; 69.7% have an incorrect answer. Four of the five tasks contain 255
  incorrect and 45 correct answers each, so class balance differs sharply by task; AUROC
  (base-rate independent) is the comparable metric.

## GSM8K

- Source: Cobbe et al. (2021); HF `openai/gsm8k`, config `main`, split `test`.
- Used only to generate trajectories with `Qwen/Qwen2.5-Math-1.5B-Instruct` for E4. The
  first 120 test questions and their gold answers (number after `####`) are cached by
  `make data`. E4 did not run on the build machine (no CUDA).

## MATH-500 / MATH

- `HuggingFaceH4/MATH-500` resolves. `hendrycks/competition_math` exists as a Hub page but
  is flagged `disabled` (its data was taken down), so it is recorded as unverified and is
  not substituted with an unofficial mirror. No experiment in this build uses MATH.

## StrategyQA

- Source: Geva et al. (2021); HF `wics/strategy-qa` resolves (card licence "other").
- Provides questions, answers and human decompositions, not model reasoning traces with
  graded answers. A failure detector cannot be evaluated on it without first generating
  traces with a model (GPU), so the StrategyQA row of E7 is `NOT_RUN`.

## PRM800K

- Source: Lightman et al. (2023); GitHub `openai/prm800k` (MIT); data files are stored
  with Git LFS. The loader reads a local checkout and takes the first step rated -1
  (PRM800K rates steps -1 / 0 / +1) as the first error. Its record layout was written
  without access to the files and is **unverified**; it raises `DatasetSchemaError` with
  the observed keys if the layout differs. PRM800K is not downloaded by `make data` and
  feeds no experiment here.
